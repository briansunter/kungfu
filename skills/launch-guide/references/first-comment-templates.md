# First Comment Templates for Product Hunt

The first comment is posted upon launch and is essential to start the discussion.
It sets the tone for the entire launch page.

## Why the First Comment Matters

- First thing visitors read after the tagline
- Sets a personal, approachable tone
- Provides context that doesn't fit in the description
- Invites discussion and feedback
- Shows the maker is engaged and responsive

## Template 1: The Builder's Story

```
Hey Product Hunt! 👋

I'm [Name], the maker of [Product].

I built [Product] because [personal problem]. After trying [existing
solutions], I realized [insight that led to building it].

What makes [Product] different:
• [Differentiator 1]
• [Differentiator 2]
• [Differentiator 3]

I'd love to hear:
- What features would you want to see next?
- Have you faced [this problem] before?

Happy to answer any questions! 🙌
```

## Template 2: Problem-First

```
Hi everyone! 👋

If you've ever [experienced common pain point], you know how frustrating
it is. [Brief elaboration on the problem].

That's why I built [Product] — it [core solution in one sentence].

A few things I'm proud of:
• [Feature/achievement 1]
• [Feature/achievement 2]
• [Feature/achievement 3]

Try it out and let me know what you think. I'm here all day to answer
questions and hear your feedback!

[Link to demo/free trial]
```

## Template 3: Metrics-Driven

```
Hey PH! 🚀

[Product] has been in beta for [time period] and the results have been
exciting:
• [Metric 1: e.g., "500+ beta users"]
• [Metric 2: e.g., "Saves an average of 3 hours per week"]
• [Metric 3: e.g., "98% retention rate"]

Today we're officially launching with [new feature or milestone].

What's coming next:
• [Roadmap item 1]
• [Roadmap item 2]

Would love your feedback — what would make [Product] a must-have for
your workflow?
```

## Template 4: Open Source

```
Hey Product Hunt! 👋

[Product] is open source and free to use. Here's why I decided to build
it in the open:

[Brief explanation of open source motivation]

The stack:
• [Tech 1]
• [Tech 2]
• [Tech 3]

Repo: [GitHub link]
Docs: [Docs link]

Contributions welcome! I've tagged several good-first-issue items for
anyone who wants to dive in.

What features would you love to see? Drop your ideas below 👇
```

## Template 5: Technical Deep-Dive

```
Hi everyone! 🛠️

I'm a [role] who built [Product] to solve [technical problem].

The technical approach:
• [Architecture decision 1 and why]
• [Architecture decision 2 and why]
• [Performance metric or benchmark]

This is different from [competitor/alternative] because [technical
differentiator].

I wrote a detailed blog post about the architecture:
[Link to technical blog post]

Happy to nerd out on the technical details — ask me anything!
```

## Writing Tips

- **Be authentic**: Write in your own voice, not marketing speak
- **Be specific**: "Saves 3 hours/week" beats "saves time"
- **Ask a question**: End with something that invites replies
- **Stay available**: Respond to every comment, especially in the first hours
- **Show vulnerability**: Sharing challenges makes you relatable
- **Keep it scannable**: Use bullet points and short paragraphs
- **Include a link**: Direct readers to try the product or see a demo
