# Boundary Setting Scripts and Communication Templates

**Source**: Solo founder operations research and burnout prevention best
practices **Confidence**: HIGH - Proven communication strategies

---

## Why Boundaries Matter

**The solo founder trap**: No boss to tell you when to stop, no colleagues to
model behavior after, no HR to enforce work-life balance.

**What happens without boundaries**:

- 60-80 hour weeks become normal
- Burnout within 6-12 months
- Resentment toward your business
- Decision quality degrades
- Health and relationships suffer

**What boundaries provide**:

- Sustainable pace (marathon, not sprint)
- Better decisions (rested brain)
- Higher productivity (focused work)
- Model behavior for future team
- Business longevity

## Email and Communication Scripts

### Setting Expectations with New Customers

**Onboarding Email Template**:

```
Subject: Welcome to [Product]! What to expect

Hi [Customer Name],

Welcome aboard! I'm [Your Name], founder of [Product].

I wanted to set expectations on support and communication:

✅ Response Times:
- Email: Within 24 hours (Mon-Fri)
- Support tickets: Within 24 hours (Mon-Fri)
- Emergencies (production down): [Phone/method]

✅ Support Hours:
- Monday-Friday: 9am-6pm PT
- Weekends: Off (responding Monday)

✅ What This Means:
- Fast responses during week
- No weekend work (burnout prevention)
- Quality over speed (thorough fixes)

I'm a solo founder, so these boundaries let me provide
great support while staying sane and building product.

Questions? Just hit reply.

Cheers,
[Your Name]
```

### Explaining Response Delays

**When You Miss 24-Hour Window**:

```
Subject: Re: [Original Subject]

Hi [Name],

Thanks for your patience! I missed my usual 24-hour response
window on this one.

[Optional: Brief reason - e.g., "Was pushing a critical
security fix," or "Had a family emergency"]

I've prioritized your message and will get back to you
by [specific time today/tomorrow] with a detailed response.

Thanks for understanding!

Best,
[Your Name]
```

### Saying No to "Urgent" Requests

**When Customer Demands Immediate Response**:

```
Subject: Re: [Original Subject]

Hi [Name],

I understand this feels urgent to you.

My support policy is 24-hour response time (Mon-Fri),
which I'll honor by [specific time].

For immediate needs:
- Check our documentation: [link]
- Search our community: [link]
- If production-down emergency: [emergency method]

Thanks for understanding that I'm one person and need
boundaries to provide great service long-term.

Best,
[Your Name]
```

## Auto-Responder Templates

### Weekend/Vacation Auto-Responder

**Weekend Template**:

```
Thanks for your message!

I'm away from my desk for the weekend and will respond
on Monday morning (within 24 hours).

If this is urgent (production down, data loss):
Emergency contact: [method]

Otherwise, I'll be in touch Monday!
- [Your Name]
```

**Vacation Template**:

```
Thanks for your message!

I'm on vacation from [start date] to [end date].
I'll respond within 24 hours of my return ([return date]).

For urgent matters during this time:
- Check our documentation: [link]
- Community support: [link]
- Emergency: [method]

Thanks for your patience!
- [Your Name]
```

### Deep Work Block Auto-Responder

**Tuesday Deep Work Template**:

```
Thanks for reaching out!

Today is my deep work day (building features, fixing bugs).
I'm unavailable for calls/real-time communication.

I'll respond to all messages within 24 hours
(Wednesday morning).

If this is urgent (production down):
Emergency contact: [method]

Thanks for understanding that focused work lets me
build [Product] better!

Best,
[Your Name]
```

## Saying "No" Scripts

### Declining Feature Requests

**Polite No**:

```
Subject: Re: Feature Request: [Feature Name]

Hi [Name],

Thanks for sharing this idea!

I've added it to our feature request tracker
for consideration. [Optional: Link to public tracker]

Can't promise when or if we'll build it, but I do
review all requests when planning our roadmap.

For now, we're focusing on [current priorities].

Thanks for understanding!
[Your Name]
```

### Declining Custom Work

**When Customer Asks for Custom Features**:

```
Subject: Re: Custom Development Request

Hi [Name],

Thanks for thinking of me for this project!

I'm not taking on custom development work right now
as I'm focused on improving [Product] for all customers.

That said, this sounds like a valuable feature.
I've added it to our roadmap for consideration.

Alternatively:
- You could build this using our [API/documentation]
- [Partner/freelancer recommendation if you have one]

Let me know if I can help with anything else!
[Your Name]
```

### Declining Meetings

**When Someone Wants to "Pick Your Brain"**:

```
Subject: Re: Coffee Chat Request

Hi [Name],

Thanks for reaching out!

I'm currently heads-down building [Product] and
not doing coffee chats or calls to protect my focus.

That said, happy to help via email:
- Send me your questions
- I'll respond within 24 hours (Mon-Fri)

For more in-depth help:
- Check my blog/posts: [link]
- Community discussions: [link]

Best of luck with [their project]!
[Your Name]
```

## Boundary Enforcement Scripts

### When Someone Crosses Boundaries

**First Time (Assume Forgot)**:

```
Subject: Re: [Their Message]

Hi [Name],

Just a friendly reminder that I'm [off/away/unavailable]
on [day/time] per my support policy.

I'll respond within 24 hours of [return time].

No worries, just wanted to set expectations!

Best,
[Your Name]
```

**Repeat Offender (Firm)**:

```
Subject: Please respect my boundaries

Hi [Name],

I've received multiple messages from you outside
my support hours this [week/month].

My boundaries (24-hour response, Mon-Fri) are how I
maintain quality service while avoiding burnout.

Please honor these boundaries. Continued disregard may
result in account termination.

Let me know if you have any questions about my support
policy.

Best,
[Your Name]
```

## Emergency Contact Setup

### Defining "Emergency"

**What counts as emergency**:

- Production downtime (all users affected)
- Data loss or security breach
- Payment processing failures (everyone)

**What does NOT count as emergency**:

- Single user can't access (non-production)
- Feature not working as expected
- "I need this now" (without production impact)

### Emergency Communication

**In your footer/signature**:

```
For emergencies (production down, data loss):
- Phone/Text: [number]
- Expected response: Within 2 hours
- Misuse will result in loss of emergency access
```

## Boundary Reset Rituals

### End-of-Day Shutdown

**Physical actions**:

1. Close all work tabs and windows
2. Write tomorrow's top 3 priorities
3. Turn on "Away" status (Slack, email, etc.)
4. Say out loud: "Work day is done"
5. Transition activity (walk, workout, shower)

**Mental actions**:

1. Review tomorrow's plan (write it down, then let go)
2. Acknowledge 3 wins from today
3. Forgive yourself for what didn't get done
4. Set intention for evening (e.g., "Be present with family")

### Weekend Transition

**Friday afternoon ritual**:

1. Weekly review (What worked? What didn't?)
2. Plan next week's top 3 priorities
3. Close all open loops (emails, tasks)
4. Set weekend intention (e.g., "No work thinking")
5. Celebrate week's wins (document progress)

---

**Remember**: Boundaries only work if you enforce them. The first few times will
feel uncomfortable. Then they become normal.
